# Git Agent Web 模式使用指南

[English Version](web-mode_en.md) | [🏠 README](../README_zh.md) | [📖 使用指南](USAGE_zh.md) | [🔧 调校指南](TUNING.md)

从 v1.0 起，Git Agent 除了 CLI，还提供了本地 Web UI，适合喜欢图形化操作的用户。

## 1. 启动 Web 服务

```bash
# 一键构建（需要本机已安装 Node.js 18+）
make build
./git-agent serve

# 指定端口 / 不自动打开浏览器
./git-agent serve --port 9000 --open=false

# 或者跳过前端构建（仅在 internal/web/dist 已存在产物时）
make build-go-only
./git-agent serve
```

默认访问地址：`http://127.0.0.1:8088`。

- 默认只监听 `127.0.0.1`，不会暴露到局域网。
- 启动后控制台打印实际访问 URL；`Ctrl+C` 优雅退出。
- 若端口被占用会直接报错，请更换 `--port`。

## 2. 打开本地目录

1. 首页点击文件夹按钮，通过**系统文件选择器**选择本地目录（也可从"最近打开"中选择）。
2. 如果目录还不是 Git 仓库，会弹出"是否初始化"对话框；点击"初始化"后系统会：
   - 执行 `git init`；
   - 生成一个默认 `.gitignore`（最小化模板）；
   - 若你尚未配置姓名/邮箱，会提示先去"设置"页填写。
3. 进入工作区后，左侧为文件树、右侧为功能面板（状态 / 历史 / 分支），右下角 🤖 按钮可打开 AI 对话助手。

系统目录（如 `/`、`$HOME`、`/etc`、`C:\Windows`）会被自动拒绝，避免误伤。

## 3. 主要功能

- **状态面板**：查看哪些文件被修改 / 新增 / 删除 / 未跟踪，支持多选提交、点击文件查看 diff、一键"保存版本"。
- **历史面板**：按作者/关键字筛选提交、查看 commit 的 diff、回滚（对未提交修改做二次确认）。
- **分支面板**：切换分支（有未提交修改会二次确认）、新建分支、推送到远程；推送失败且检测到需要先拉取时会给出提示。
- **AI 对话助手**：右侧抽屉式面板，用自然语言告诉 Agent 你的需求。UI 会**流式展示** ReAct 过程（思考 → 调用工具 → 工具结果 → 最终回复），推理步骤默认折叠，点击可展开查看详情。
- **文件预览**：点击文件树中的文件，以悬浮弹窗方式查看文件内容，支持语法高亮。
- **多工作区**：顶部切换栏可同时挂多个目录；每个工作区拥有独立的 `Agent`、对话历史、状态。

## 4. 设置页

- **用户信息**：设置 Git 提交署名（姓名 / 邮箱）。
- **LLM 配置**：填写 API Key / Base URL / 模型，支持"测试连接"。
  - API Key 前端以掩码 `sk-****xxxx` 显示，留空即保持现有不变。
- **HTTP 认证**：用于 https:// 远程仓库推送的用户名 + 令牌。

配置保存在 `~/.git-agent/config.json`（权限 `0600`）。优先级：命令行参数 > 环境变量 > 配置文件 > 默认值。

## 5. 数据与日志

| 文件 | 说明 |
|------|------|
| `~/.git-agent/config.json` | 用户配置（脱敏存储） |
| `~/.git-agent/recent.json` | 最近打开目录列表（最多 20 条） |
| `~/.git-agent/logs/ops.log` | 破坏性操作审计（回滚、切分支、推送、init） |

## 6. 与 CLI 并存

Web 模式是新增入口，完全不影响原有 CLI：

```bash
./git-agent          # 继续按原有方式使用 CLI
./git-agent serve    # 启动 Web 服务
./git-agent --help   # 查看全部命令
```

## 7. 安全提示

- 默认只监听 `127.0.0.1`，外部机器无法访问。
- 如需在局域网访问，需显式加 `--host 0.0.0.0 --i-know-what-i-do`，且强烈建议自行在外层加访问控制。
- 文件读取接口做了路径穿越校验，只允许访问 workspace 根目录下的文件。

## 8. 常见问题

- **启动后页面空白？** 说明前端资源未被正确嵌入。请确认 `internal/web/dist/` 下存在 `index.html`；用 `make build-web` 重新构建前端。
- **对话面板没有流式效果？** 检查浏览器 DevTools 的 Network 面板是否看到 `event-stream` 的长连接；反向代理请关闭缓冲（`X-Accel-Buffering: no`）。
- **提交时报"请先设置用户"？** 到"设置 → 用户信息"填写姓名/邮箱后再试。
- **AI 对话报错？** 确认已在设置页配置 LLM API Key 并测试连接成功。修改后端代码后需重启服务（或使用 `make dev-server` 配合 air 自动重启）。

## 9. 开发调试

项目支持前后端同时热加载，修改代码后无需手动重启：

```bash
# 安装 air（一次性，用于 Go 后端热加载）
go install github.com/air-verse/air@latest

# 方式 A：两个终端
make dev-server   # 终端 1：后端（Go 代码修改自动重启）
make dev-web      # 终端 2：前端（Vite HMR，.vue/.ts 修改实时生效）

# 方式 B：一个终端
make dev-all      # 同时启动前后端热加载
```

访问 `http://localhost:5173`，Vite 会把 `/api` 代理到后端 `:8088`。

> ⚠️ **注意**：前端修改（`.vue`、`.ts`、`.css`）通过 Vite HMR 实时生效；后端修改（`.go`）需要 air 自动重编译重启（约 1-2 秒延迟）。如果未安装 air，后端修改需手动重启 `make dev-server`。
